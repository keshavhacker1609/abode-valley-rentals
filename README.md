# Abode Valley Rentals

Rental brokerage site for 2.75 BHK and 3 BHK flats at Abode Valley, Kattankulathur (Chennai), plus nearby co-living rooms.
Next.js 14 (App Router) · TypeScript · Tailwind · Framer Motion · GSAP/ScrollTrigger · Lenis · SplitType · Swiper · Leaflet.

Brand, contact details, inventory, amenities, distances, FAQs and copy all come from **`.env` and `/data/*.json`**. Nothing is hard-coded in components.

## Quick start

```bash
npm install
cp .env.example .env.local      # fill in name, phone, email, address, ADMIN_PASS
npm run dev                     # http://localhost:3000
```

Production check: `npm run build && npm start`.

## Adding your photos

1. Save photos in **`public/images/_incoming/`**, named after their slot:

   | Photo | File name |
   |---|---|
   | Aerial with pool and towers (home hero) | `hero-aerial-pool.jpg` |
   | Second aerial (Location page hero) | `aerial-pool-towers.jpg` |
   | Entrance gate with the sign | `entrance-gate.jpg` |
   | Site plan (Block Explorer) | `site-plan.jpg` |
   | Interiors, amenities, blocks… | see **IMAGE_SLOTS.md** for every name |

2. Run `npm run images:import`. Each photo is converted to WebP at the right path and the blur-up previews are regenerated.

Until a slot is filled, an on-brand placeholder labelled with its slot name is shown.
**Site plan hotspots** use `plan.x` / `plan.y` (percent of the image) in `scripts/generate-data.mjs → PLAN`. If your plan image is cropped differently, nudge those numbers and run `npm run data:generate`.

> Only use photos you own or have permission for. A site plan downloaded from a listings portal (e.g. one with a watermark) usually isn't licensed for reuse, so ask the developer for the brochure version.

## Inventory model

`data/flats.json` holds one flat per line, generated by `scripts/generate-data.mjs` (deterministic seed):

- **22 blocks** as on the site plan: A–H, J–N, P–T, V, W, Y, Z (no I, O, U, X)
- **4 floors × 8 flats** per block = 32 per block, 704 total. IDs like `C-308` (3rd floor, unit 8)
- Each floor has two cores of four; units 1, 4, 5, 8 are corner **3 BHK**, units 2, 3, 6, 7 are **2.75 BHK**
- Fields: id, block, floor, unitNo, type, sqft, facing, furnishing, rent, deposit, maintenance, availableFrom, status, tenantPref, parking, petsAllowed, images[], highlights[]

Change the shape with env vars, e.g. `FLOORS=5 UNITS_PER_FLOOR=8 npm run data:generate`, or `BLOCKS=ABCDEFGHIJKLMNOPQRSTUVWXYZ` for all 26 letters. The whole UI (filters, explorer matrix, stats, sitemap) adapts.

Other data: `blocks.json` (generated), `coliving.json`, `amenities.json`, `location.json` (coordinates + distances; verify the estate pin), `faqs.json`, `testimonials.json`, `process.json`, `content.json` (hero copy).

## Keeping availability current

Values are layered: **seed JSON ← Google Sheet (optional) ← /admin edits**.

- **/admin**: sign in with `ADMIN_PASS`, then change status, rent, deposit, maintenance and available-from per flat. Pages revalidate instantly.
  - Locally, edits go to `data/overrides.json`.
  - **On Vercel** the filesystem is read-only, so create a free Upstash Redis database and set `UPSTASH_REDIS_REST_URL` and `UPSTASH_REDIS_REST_TOKEN`.
- **Google Sheet as CMS**: File → Share → Publish to web → CSV, then set `SHEET_CSV_URL`. Columns: `id,status,rent,deposit,maintenance,availableFrom,furnishing` (any subset). Refreshes every `SHEET_REVALIDATE` seconds.

## Leads

Enquiry, visit-booking, owner-listing and callback forms are validated with zod on both client and server, with a honeypot and rate limiting. They POST JSON to `ENQUIRY_WEBHOOK_URL` (Slack, Zapier, Make or Google Apps Script). Without a webhook they're logged to the server console. Every form also offers a prefilled WhatsApp deep link.

## Deploy to Vercel

1. Push to GitHub and import the repo in Vercel (framework auto-detected).
2. Add the env vars from `.env.example`. Set `NEXT_PUBLIC_SITE_URL` to your domain; it's used for canonical URLs, the sitemap and JSON-LD.
3. Add Upstash variables if you'll use /admin in production.

## Motion & accessibility notes

- The preloader (logo stroke draw → curtain) shows once per session, on desktop only.
- Split-line headline reveals, parallax hero, pinned horizontal "Why" section, magnetic buttons, custom cursor (fine pointers only), cascading block matrix, Framer layout animations on filters and route transitions.
- Everything respects `prefers-reduced-motion`. Text colours meet WCAG AA in both themes (terracotta is split into a decorative tone and an AA-safe "ink" tone).
